REDESIGN DE INTERAÇÃO: DA ANÁLISE AO PROTÓTIPO

SOBRE A ATIVIDADE:

Esta atividade propõe que seu time analise a proposta inicial da home da Iara Games e identifique problemas de design de interação, analise esses problemas com base nos conceitos estudados e proponha uma reformulação, entregando um documento de análise e um protótipo funcional ou navegável.

FORMAÇÃO DOS GRUPOS:

Grupos de até 5 integrantes.
Todos os nomes devem constar no PDF entregue.
ETAPAS DA ATIVIDADE:

1. Escolha do site:

O grupo deve observar o que já foi desenvolvido para a home da plataforma Iara Games e apresente problemas de design de interação. Podem se inspirar nos exemplos do capítulo ou buscar novas referências na web.

Sugestões de categorias para buscar: E-commerce, portais de notícias, sites de prefeitura ou governo, portais educacionais, sites de serviços financeiros.

2. Análise crítica:

Com base nos conceitos de Cooper (2014) e no capítulo estudado, o time deve identificar e descrever os problemas de interação na atual, classificando-os conforme as categorias abaixo:

O site é rude com o usuário? Culpa o usuário por seus erros?
Exige que o usuário pense como um computador?
Apresenta hábitos desleixados (formulários sem validação, feedbacks ausentes)?
Deixa trabalho pesado para o usuário realizar manualmente?
A estética remete a décadas anteriores, prejudicando a confiança no site?
Lembre-se: incluam capturas de tela anotadas no PDF para ilustrar cada problema identificado.

3. Proposta de melhoria:

Para cada problema encontrado, o grupo deve descrever a solução proposta, explicando:

O que será reformulado e por quê.
Como a mudança melhora a experiência do usuário.
Quais padrões de interação modernos serão aplicados. 4. Protótipo:

O grupo deve criar um protótipo da interface reformulada. Escolham uma das opções a seguir:

HTML + CSS

- Repositório público no GitHub com o código da interface reformulada.

- O protótipo deve ser navegável via GitHub Pages ou ferramenta similar.

- O link do repositório e do deploy devem constar no PDF.

Figma

- Protótipo navegável no Figma com ao menos as telas principais reformuladas.

- O link de visualização pública deve constar no PDF.

- Verifique o acesso antes de entregar.

Atenção: o protótipo não precisa ser funcional na totalidade. O foco deve estar nas telas e interações que o grupo identificou como problemáticas

O que entregar:

1. PDF com a análise completa:

O documento deve conter: identificação do grupo, URL do site analisado, análise de cada problema com capturas de tela anotadas, proposta de melhoria para cada problema identificado e link do protótipo.

Link do repositório GitHub (para quem optar por HTML + CSS)

- Repositório público com README explicando como visualizar o protótipo.

- Inclua o link do deploy.

OU

Link do Figma (para quem optar por Figma)

- Protótipo com permissão de visualização pública habilitada.

Atenção: todos os links devem estar acessíveis no momento da entrega. Links quebrados ou com acesso restrito não serão avaliados.
